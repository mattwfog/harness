# dispobench-core (v2): the verdict engine in OCaml

Scope: **runners and adapters stay in the host language** (agents
under test are Python/TS; in-process adapters are the composability
story). What moves to OCaml is the **verdict layer** — everything that
reads persisted JSONL and produces judgments:

    schemas + validation · matrix (MECE) · detectors · report · lock/gate

shipped as ONE static binary (`dispobench-core`) with subcommands
mirroring the CLI: `validate | matrix | detect | report | gate`. The
JSONL contracts (VERDICT_SPEC.md C1/C2/C5) are the frozen boundary — the Python
packages are replaced incrementally, zero adapter churn, and the Python
test suite (78 tests) becomes the conformance oracle: for the same
records, the binary's JSON outputs must be byte-identical to the Python
report emitter's before any Python package is retired.

## Why OCaml here is not aesthetics

- **P1 becomes a type.** `type detector = record -> verdict option` with
  no IO in the signature — a detector that phones an LLM does not
  compile. The "zero LLM references" grep audit retires.
- **P2 becomes exhaustiveness.** Detectors are a variant type; the
  column mapping is a total function over it. A detector with no home,
  or two, is a compile error. `validate` still checks user-supplied
  matrix.json files at runtime for third-party detectors.
- **Distribution.** A static binary makes `dispobench-core gate` a
  zero-dependency pre-push hook for ANY repo in any language — stronger
  worldwide composability than requiring a Python environment.
- **Speed.** Full-grid scoring over millions of records becomes trivial.

## Architecture

```
verdict/
  dune-project
  bin/main.ml            subcommand dispatch
  lib/
    record.ml            C1 parse/validate (yojson), stable hashing
    matrix.ml            partitions, MECE validation, exhaustive homes
    detectors.ml         stdlib detectors (pure; regex via re)
    detect_ext.ml        third-party detector protocol: an external
                         command fed records on stdin, verdicts on
                         stdout (JSONL) — host-language detectors keep
                         working; purity enforced by contract + replay
                         determinism check, not types (documented gap)
    wilson.ml            intervals
    report.ml            grid + emitters, byte-deterministic
    lock.ml              sha256 shaping lock, gate compare
  test/                  alcotest; golden files generated by the Python
                         suite (the conformance oracle)
```

Dependencies: `yojson`, `re`, `digestif`, `cmdliner`, `alcotest` (test).
No network library in scope at all — the runner (host language) owns all
IO with models.

## Migration ladder (each rung independently shippable)

1. Toolchain: `opam switch create 5.2.x` + dune (opam present on the
   build machine; no switch installed as of 2026-09-01).
2. `record.ml` + `matrix.ml` + `lock.ml` → `dispobench-core validate|matrix|gate`
   replaces the Python gate in pre-push hooks (first visible win).
3. `detectors.ml` + `wilson.ml` + `report.ml` → `detect|report`;
   golden-file parity against the Python emitters on the conformance
   fixtures AND on a real production run's records.
4. Python packages `core/detectors/report` become thin wrappers calling
   the binary, then retire; `runner/` and adapters stay Python forever.

## Out of scope

Rewriting runners/adapters; any IO in detectors; judge anything.
